30/**
31 * Dead-simple collection (essentially a statically-sized array) of up-to-`N` `Stat_set`s, for use
32 * as a lightning-fast way to choose a category and update the `Stat_set` relevant to it.
33 *
34 * So, for example, stats_default() and stats_mutable_default() (a/k/a `stats[_mutable]<0>()`) resolves to,
35 * basically, at compile-time, `(Stat_set*)this + 0`; whereas `stats[_mutable]_at(idx_for_a_particular_category)`
36 * resolves to `(Stat_set*)this + idx_for_a_particular_category` at run-time. Either way, it is just about
37 * as quick as a quasi-associative lookup can be. We've consciously avoided anything dynamic like a hash-map,
38 * or even a `vector` (which, while quick for a read-only lookup, could involve reallocations and associated
39 * difficulties). Dead-simple.
40 *
41 * It really *is* an `array<Stat_set, S_N>` -- initialized to hold #S_N default-constructed `Stat_set`s --
42 * albeit with syntactic sugar for convenient/expressive access.
43 *
44 * @note As a consequence, it is copy-ctible and copy-assignable if and only if the aforementioned `array`
45 * type is. To wit: `Stat_set` is <=> a `Stat_set_list<Stat_set, N>` is. This simple semantic is
46 * why this class template lacks constructors (as does `array` generally).
47 *
48 * Hence:
49 * - `Stat_set_list<Stat_set, N> stats;` // Constructs N things like this: Stat_set{}.
50 * - `auto stats2 = stats;` // Constructs N more like this: Stat_set{stats[idx]}.
51 *
52 * @see Global_stats which can provide global-singleton access to a Stat_set_list.
53 *
54 * @tparam Stat_set_t
55 * #Stat_set is a `Stat_set` of your choice, subject to the patterns and requirements
56 * documented in the namespace util::stat doc header. An additional requirement in this context is
57 * it must be default-constructible: `Stat_set{}`. (It would not be impossible to loosen this
58 * requirement, but it brings certain conveniences, so to the extent the requirement can survive the
59 * user's needs over time, it should.)
60 * @tparam N
61 * The number of `Stat_set`s `*this` can hold. Informally speaking, this does not mean all #S_N
62 * slots *must* be actively used. A suggested pattern is: some module may want to, in the future,
63 * hold 2+ `Stat_set`s depending on the category; but in the meantime it can use `S_N == 1` and
64 * `stats_[mutable_]default()` for everything. Adding more fine-grained stat-keeping later, then, could
65 * involve few to no breaking API changes in this module: perhaps some alias would change from
66 * `using Stats = flow::util::Stat_set_list<My_cool_stats, 1>` to
67 * `using Stats = flow::util::Stat_set_list<My_cool_stats, MAX_COOL_STAT_CATEGORY>`, while
68 * an accessor would remain `Stats& stats()`.
69 */

164/**
165 * A straightforward global/singleton holder of a single `Stat_set_list<Stat_set, S_N>`; the template parameter
166 * #Tag is used to arrange for an independent such `Stat_set_list` per distinct #Tag type.
167 *
168 * The `static` accessor get() is the API:
169 * - get() shall thread-safely construct the `Stat_set_list` the first time it is invoked (even before/after
170 * `main()`).
171 * - get() shall subsequently return ref to that same `Stat_set_list`.
172 * - `Global_stats<Tag, Stat_set, S_N>::get()` shall always return the same address.
173 * - Each distinct, compile-time value of the tuple (#Tag, #Stat_set, #S_N) shall yield
174 * a distinct address returned by get().
175 *
176 * Performance: get() is almost identical in performance to simply returning the value of a `static`/global
177 * pointer variable. In practice it is 1-2 cycles costlier; this is negligible in 99.9999999999% of situations.
178 *
179 * @note One can, instead, simply maintain their own `Stat_set_list<My_cool_stats, NUM_CATS> s_stat_sets`, or
180 * their own on-demand `static` getter. Global_stats provides an alternative way of organizing global
181 * access to such a thing, with segregation by #Tag and on-demand creation; that's all. Your call!
182 *
183 * @tparam Tag_t
184 * #Tag can be any type and is used exclusively (and exclusively at compile-time) to disambiguate
185 * 1+ `Stat_set_list`s with the same #Stat_set and #S_N.
186 * @tparam Stat_set_t
187 * See Stat_set_list.
188 * @tparam N
189 * See Stat_set_list.
190 */
191template<typename Tag_t, typename Stat_set_t, size_t N>
192class Global_stats
193{
194public:
195 // Types.
196
197 /// The template parameter `Tag_t`.
198 using Tag = Tag_t;
199
200 /// See Stat_set_list.
201 using Stat_set = Stat_set_t;
202
203 // Constants.
204
205 /// See Stat_set_list.
206 static constexpr size_t S_N = N;
207
208 // Methods.
209
210 /**
211 * Thread-safely default-constructs or accesses the one `Stat_set_list<Stat_set, S_N>` for #Tag.
212 * @return See above.
213 */
214 static Stat_set_list<Stat_set, N>& get();
215
216private:
217 // Constructors/destructor.
218
219 /// Forbid instantiation, for it is pointless.
220 Global_stats() = delete;
221}; // class Global_stats

278template<typename Tag_t, typename Stat_set_t, size_t N>
279Stat_set_list<Stat_set_t, N>& Global_stats<Tag_t, Stat_set_t, N>::get() // Static.
280{
281 /* Construct once per <Tag, Stat_set, N> tuple per process.
282 * Compared to just having a static s_singleton data member and returning it here:
283 * - avoids static-init-ordering hell (will be constructed on-demand);
284 * - (after the initial construct) is 1-2 cycles slower (negligible). */
285 static Stat_set_list<Stat_set, S_N> s_singleton;
286 return s_singleton;
